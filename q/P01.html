実践 1 売上分析

月次売上レポート

（経営企画の課長より）来週の経営会議で、2025年の売上がどう推移したかを見せたいんだ。月ごとの売上をまとめてもらえる？件数も分かるとうれしい。グラフにするつもりだから、そのまま使える形だと助かるよ。

この問題を解く（SQLを書く）

ブラウザだけで動きます。登録は不要です。

自分で確認しよう

実践問題には決まった答えがありません。結果が出たら、次の点を確かめてから、問題の画面で「完了」にしましょう。

  • キャンセル（cancelled）と返品（returned）の注文を売上から除いたか。除く・別に出す、どちらにしても理由を説明できるか。
  • 発送済み・未着（shipped）の注文を売上に含めるか決めたか（12月末の注文が該当する）。
  • 売上金額に送料を含めるか決め、列名などで分かるようにしたか。
  • 注文が1件もない月（2025年8月）が結果から抜けていないか。グラフにするなら 0 の行があったほうがよいか考えたか。
  • 「件数」が注文の件数なのか明細の行数なのか、意図どおりに数えているか（JOIN 後に COUNT(*) すると明細の行数になる）。
  • 月の合計を足すと、年間の売上と一致するか。
ヒント

「売上」にどの注文（status）を含めるか、送料を含めるかを先に決めましょう。注文が1件もない月があると GROUP BY だけではその月の行が出ません。月の一覧を再帰CTEで作って LEFT JOIN する方法があります。

解答例を見る

解答例 1

SELECT strftime('%Y-%m', o.ordered_on) AS 年月,
       COUNT(DISTINCT o.id) AS 注文件数,
       SUM(oi.quantity * oi.unit_price) AS 売上金額
FROM orders o
JOIN order_items oi ON oi.order_id = o.id
WHERE o.status IN ('delivered', 'shipped')
GROUP BY strftime('%Y-%m', o.ordered_on)
ORDER BY 年月

解釈: 売上は delivered と shipped の注文の商品代金（送料は含めない）。件数は注文の件数（COUNT(DISTINCT o.id)）。長所: いちばん素直で、社内の「売上」の定義（キャンセル・返品を除く）に合う。注意点: 注文のない8月の行が出ないので、そのままグラフにすると8月が飛ばされて推移を読み違える。

解答例 2

WITH RECURSIVE months(ym) AS (
  SELECT '2025-01'
  UNION ALL
  SELECT strftime('%Y-%m', ym || '-01', '+1 month') FROM months WHERE ym < '2025-12'
),
order_totals AS (
  SELECT o.id, strftime('%Y-%m', o.ordered_on) AS ym, o.status,
         SUM(oi.quantity * oi.unit_price) AS amount
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.id
  GROUP BY o.id, o.ordered_on, o.status
)
SELECT m.ym AS 年月,
       COUNT(CASE WHEN t.status IN ('delivered', 'shipped') THEN 1 END) AS 有効注文件数,
       COALESCE(SUM(CASE WHEN t.status IN ('delivered', 'shipped') THEN t.amount END), 0) AS 売上金額,
       COUNT(CASE WHEN t.status IN ('cancelled', 'returned') THEN 1 END) AS キャンセル返品件数,
       COALESCE(SUM(CASE WHEN t.status IN ('cancelled', 'returned') THEN t.amount END), 0) AS キャンセル返品金額
FROM months m
LEFT JOIN order_totals t ON t.ym = m.ym
GROUP BY m.ym
ORDER BY m.ym

解釈: 1月〜12月の全ての月を出し、8月は 0 とする。キャンセル・返品は売上から除いたうえで、別の列に件数と金額を出す。長所: グラフにしても月が飛ばない。「キャンセルが多い月」も同時に見られ、会議で質問されても答えやすい。注意点: 先に注文ごとの合計（order_totals）を作ってから月で集計している。明細を直接 JOIN して COUNT(*) すると件数が明細の行数になってしまう。

解答例 3

WITH RECURSIVE months(ym) AS (
  SELECT '2025-01'
  UNION ALL
  SELECT strftime('%Y-%m', ym || '-01', '+1 month') FROM months WHERE ym < '2025-12'
),
order_totals AS (
  SELECT o.id, strftime('%Y-%m', o.ordered_on) AS ym, o.shipping_fee,
         SUM(oi.quantity * oi.unit_price) AS amount
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.id
  WHERE o.status = 'delivered'
  GROUP BY o.id, o.ordered_on, o.shipping_fee
)
SELECT m.ym AS 年月,
       COUNT(t.id) AS 配達済み注文件数,
       COALESCE(SUM(t.amount), 0) AS 商品売上,
       COALESCE(SUM(t.shipping_fee), 0) AS 送料,
       COALESCE(SUM(t.amount + t.shipping_fee), 0) AS 送料込み売上,
       CAST(ROUND(AVG(t.amount)) AS INTEGER) AS 平均客単価
FROM months m
LEFT JOIN order_totals t ON t.ym = m.ym
GROUP BY m.ym
ORDER BY m.ym

解釈: 「確定した売上」だけを見たいと考え、配達済み（delivered）のみを対象にした。送料を含む・含まないの両方と、1注文あたりの平均（客単価）を出す。長所: 経理の数字（入金ベース）と比べやすい。送料の影響も分かる。注意点: 12月末の shipped（未着）を含めないので、解答例1・2より12月の売上が小さくなる。8月の平均客単価は注文がないため NULL（空欄）になる。どの定義を使ったかを資料に書き添える。
