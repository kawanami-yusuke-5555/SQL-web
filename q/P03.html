実践 3 顧客分析

リピート率を知りたい

（マーケティング部長より）うちのお店って、リピートしてくれるお客さんはどのくらいいるの？2回以上買ってくれた人の割合をざっくり知りたい。2025年の数字でいいよ。

この問題を解く（SQLを書く）

ブラウザだけで動きます。登録は不要です。

自分で確認しよう

実践問題には決まった答えがありません。結果が出たら、次の点を確かめてから、問題の画面で「完了」にしましょう。

  • 割合の分母を「購入したことがある人」にしたか「会員全員」にしたかを決め、結果に明示したか。
  • キャンセル・返品の注文を「購入1回」と数えていないか。
  • 同じ日に2回注文した人を「2回」と数えるか「1日=1回」と数えるか考えたか（同じ顧客が同じ日に2件注文しているデータがある）。
  • 会員テーブルにいない顧客ID（退会して削除された顧客）の注文を、数えるか除くか決めたか。
  • 整数の割り算で 0 や切り捨てになっていないか。割合の丸め方を決めたか。
ヒント

顧客ごとの購入回数を先に集計し（CTE かサブクエリ）、その結果を数えます。割合は 100.0 * 分子 / 分母 のように小数にしてから割ります（整数どうしの割り算は切り捨て）。分母を何にするかで値が変わります。

解答例を見る

解答例 1

WITH per_customer AS (
  SELECT customer_id, COUNT(*) AS cnt
  FROM orders
  WHERE status IN ('delivered', 'shipped')
  GROUP BY customer_id
)
SELECT COUNT(*) AS 購入者数,
       SUM(CASE WHEN cnt >= 2 THEN 1 ELSE 0 END) AS リピーター数,
       ROUND(100.0 * SUM(CASE WHEN cnt >= 2 THEN 1 ELSE 0 END) / COUNT(*), 1) AS "リピート率(%)"
FROM per_customer

解釈: 分母は「有効な注文が1件以上ある人」、リピーターは「有効な注文が2件以上ある人」。orders だけで数えるので、会員テーブルにいない顧客ID の注文も1人として数える。長所: 1行で答えが出て、「買った人のうち何割がまた買ったか」という一般的なリピート率になる。注意点: 同じ日の2件の注文も2回と数える。二重登録の人は2人として数えている。

解答例 2

WITH person AS (
  SELECT id AS customer_id,
         MIN(id) OVER (PARTITION BY name, birth_date, email) AS person_id
  FROM customers
),
visits AS (
  SELECT p.person_id, COUNT(DISTINCT o.ordered_on) AS days
  FROM person p
  JOIN orders o ON o.customer_id = p.customer_id
  WHERE o.status IN ('delivered', 'shipped')
  GROUP BY p.person_id
)
SELECT (SELECT COUNT(DISTINCT person_id) FROM person) AS 会員数_名寄せ後,
       COUNT(*) AS 購入者数,
       SUM(CASE WHEN days >= 2 THEN 1 ELSE 0 END) AS リピーター数,
       ROUND(100.0 * SUM(CASE WHEN days >= 2 THEN 1 ELSE 0 END) / COUNT(*), 1) AS "購入者に対するリピート率(%)",
       ROUND(100.0 * SUM(CASE WHEN days >= 2 THEN 1 ELSE 0 END)
             / (SELECT COUNT(DISTINCT person_id) FROM person), 1) AS "会員に対するリピート率(%)"
FROM visits

解釈: 氏名・生年月日・メールが同じ会員を同じ人とみなしてまとめ（名寄せ）、購入回数は「注文した日の数」で数える（同じ日の2件は1回）。分母は購入者と会員全員の両方を出す。長所: 「実際の人」と「来店の回数」に近い数字になり、2つの分母を並べることで率の意味の違いを説明できる。注意点: 会員テーブルにいない顧客ID の注文は JOIN で落ちる。名寄せの条件（何が同じなら同じ人か）は仮のもので、業務の担当者に確認が必要。

解答例 3

WITH per_customer AS (
  SELECT customer_id, COUNT(*) AS cnt
  FROM orders
  WHERE status IN ('delivered', 'shipped')
  GROUP BY customer_id
)
SELECT CASE WHEN cnt >= 5 THEN '5回以上' ELSE cnt || '回' END AS 購入回数,
       COUNT(*) AS 人数,
       ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS "構成比(%)"
FROM per_customer
GROUP BY CASE WHEN cnt >= 5 THEN '5回以上' ELSE cnt || '回' END
ORDER BY MIN(cnt)

解釈: 割合を1つの数字にまとめず、購入回数ごとの人数の分布で見せる。長所: 「2回で止まる人が多い」「ヘビーユーザーが一部にいる」など、施策のヒントまで読み取れる。1回の人の構成比を 100 から引けばリピート率になる。注意点: 「ざっくり知りたい」という依頼に対しては情報が多いので、解答例1の数字と一緒に補足資料として出すのがよい。
