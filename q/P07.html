実践 7 商品分析

レビュー評価と売上の関係

（カスタマーサポートのリーダーより）レビューの評価が高い商品って、ちゃんと売れているんでしょうか？レビューに力を入れるべきか判断したいので、評価と売上の関係が分かるものを出してもらえますか？

この問題を解く（SQLを書く）

ブラウザだけで動きます。登録は不要です。

自分で確認しよう

実践問題には決まった答えがありません。結果が出たら、次の点を確かめてから、問題の画面で「完了」にしましょう。

  • レビューと明細をそのまま JOIN して集計し、件数や売上が水増しされていないか（商品ごとに集計してから結合したか）。
  • 同じ顧客が同じ商品に複数回レビューしているデータを、そのまま数えるか、最新の1件にするか決めたか。
  • 注文が1件もない顧客のレビュー（購入していない人の評価）を含めるか決めたか。
  • レビューのない商品や売れていない商品を結果に含めたか、除いたか。その理由を説明できるか。
  • 「売上」を金額で見るか数量で見るか、キャンセル・返品を除いたかを決めたか。
  • レビュー件数が少ない商品の平均評価を、他と同じ重みで比べてよいか考えたか。
ヒント

レビューの平均評価と売上は、それぞれ商品ごとに集計してから商品で結合します（2つを先に JOIN してから集計すると、行が掛け算で増えて合計が狂います）。レビューのデータに、同じ人の重複や、購入していない人の投稿がないかも確かめましょう。

解答例を見る

解答例 1

WITH rv AS (
  SELECT product_id, AVG(rating) AS avg_rating, COUNT(*) AS n
  FROM reviews
  GROUP BY product_id
),
sales AS (
  SELECT oi.product_id, SUM(oi.quantity) AS qty, SUM(oi.quantity * oi.unit_price) AS amount
  FROM order_items oi
  JOIN orders o ON o.id = oi.order_id
  WHERE o.status IN ('delivered', 'shipped')
  GROUP BY oi.product_id
)
SELECT p.id AS 商品ID,
       p.name AS 商品名,
       ROUND(rv.avg_rating, 2) AS 平均評価,
       rv.n AS レビュー件数,
       COALESCE(s.qty, 0) AS 販売数量,
       COALESCE(s.amount, 0) AS 売上金額
FROM products p
JOIN rv ON rv.product_id = p.id
LEFT JOIN sales s ON s.product_id = p.id
ORDER BY rv.avg_rating DESC, p.id

解釈: レビューのある商品について、全レビューの平均評価と件数、2025年の販売数量・売上金額（delivered・shipped）を並べる。長所: 商品ごとの具体的な数字が見られ、「評価は高いのに売れていない商品」などを個別に拾える。注意点: 重複レビューや購入していない人のレビューもそのまま数えている。レビューのない商品は出ないので、「レビューがあるから売れる」のか比べることはできない。

解答例 2

WITH cleaned AS (
  SELECT r.product_id, r.rating,
         ROW_NUMBER() OVER (PARTITION BY r.customer_id, r.product_id
                            ORDER BY r.posted_on DESC, r.id DESC) AS rn
  FROM reviews r
  WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = r.customer_id)
),
rv AS (
  SELECT product_id, AVG(rating) AS avg_rating
  FROM cleaned
  WHERE rn = 1
  GROUP BY product_id
),
sales AS (
  SELECT oi.product_id, SUM(oi.quantity) AS qty, SUM(oi.quantity * oi.unit_price) AS amount
  FROM order_items oi
  JOIN orders o ON o.id = oi.order_id
  WHERE o.status IN ('delivered', 'shipped')
  GROUP BY oi.product_id
),
banded AS (
  SELECT p.id,
         CASE WHEN rv.product_id IS NULL THEN 5
              WHEN rv.avg_rating >= 4.5 THEN 1
              WHEN rv.avg_rating >= 4.0 THEN 2
              WHEN rv.avg_rating >= 3.0 THEN 3
              ELSE 4 END AS band_no,
         COALESCE(s.qty, 0) AS qty,
         COALESCE(s.amount, 0) AS amount
  FROM products p
  LEFT JOIN rv ON rv.product_id = p.id
  LEFT JOIN sales s ON s.product_id = p.id
)
SELECT CASE band_no WHEN 1 THEN '4.5以上' WHEN 2 THEN '4.0以上4.5未満'
                    WHEN 3 THEN '3.0以上4.0未満' WHEN 4 THEN '3.0未満'
                    ELSE 'レビューなし' END AS 平均評価の帯,
       COUNT(*) AS 商品数,
       SUM(qty) AS 販売数量の合計,
       CAST(ROUND(AVG(amount)) AS INTEGER) AS 一商品あたりの平均売上
FROM banded
GROUP BY band_no
ORDER BY band_no

解釈: レビューを整えてから（同じ人の同じ商品へのレビューは最新の1件だけ、注文が1件もない人のレビューは除く）、商品を平均評価の帯に分け、帯ごとに1商品あたりの平均売上を比べる。レビューのない商品も1つの帯にする。長所: 「評価が高い帯ほど売れているか」という依頼の問いに直接答えられる。データの不整合が平均評価をゆがめるのを防げる。注意点: 帯ごとの商品数が少ないと、1商品の売上で平均が大きく動く。「売れているから評価が集まる」逆の因果もありうるので、結論は慎重に伝える。購入者かどうかを「その商品を買ったか」まで厳しく見るかは依頼者と相談する。
