上級 14 LAG・LEAD

前回の注文からの日数

会員ID が 3 と 12 の会員の注文について、前回の注文日と、前回の注文から何日たったかを取り出してください。対象は status が 'delivered' または 'shipped' の注文だけで、「前回」も同じ会員の、この条件の注文の中で数えます（キャンセル・返品の注文は前回に数えません）。会員ごとに注文日の古い順に並べ、同じ日に2件あるときは注文ID の小さい方を先の注文とします（同じ日の2件目は 0 日になります）。各会員の最初の注文は、前回の注文日と日数を NULL にします。日数は julianday の差を CAST(... AS INTEGER) で整数にします。列は customer_id, 注文ID（orders.id）, ordered_on, 前回の注文日, 日数 の順で、customer_id の小さい順、同じ会員の中では注文日の古い順、同じ日なら注文ID の小さい順に並べます。

ヒント

LAG(ordered_on) OVER (PARTITION BY customer_id ORDER BY ordered_on, id) で、同じ会員の1つ前の注文日が取れます。日付の差は julianday(後の日) - julianday(前の日) で日数になります。

模範解答と解説を見る 
WITH valid AS ( SELECT id, customer_id, ordered_on FROM orders WHERE status IN ('delivered', 'shipped') AND customer_id IN (3, 12)), with_prev AS ( SELECT customer_id, id, ordered_on, LAG(ordered_on) OVER (PARTITION BY customer_id ORDER BY ordered_on, id) AS prev_on FROM valid) SELECT customer_id, id, ordered_on, prev_on, CAST(julianday(ordered_on) - julianday(prev_on) AS INTEGER) AS days FROM with_prev ORDER BY customer_id, ordered_on, id

LAG に PARTITION BY customer_id を付けると、会員が変わったところで「前の行」がリセットされ、各会員の最初の注文は NULL になります。PARTITION BY を忘れると、会員12 の最初の注文に会員3 の最後の注文日が入ってしまいます。キャンセルの注文（会員3 の order 124、会員12 の order 60）を先に除いておかないと、「前回」がキャンセルした注文になります。
