実践 4 在庫管理

発注したほうがいい商品

（物流部の部長より）年末年始で在庫が心配なんだ。そろそろ発注したほうがいい商品をリストアップしてくれる？今日は 2026-01-01 だよ。

この問題を解く（SQLを書く）

ブラウザだけで動きます。登録は不要です。

自分で確認しよう

実践問題には決まった答えがありません。結果が出たら、次の点を確かめてから、問題の画面で「完了」にしましょう。

  • 「発注が必要」の基準を、在庫数の絶対値にしたか、売れるペース（何か月分の在庫があるか）にしたか。その理由を説明できるか。
  • 廃番の商品（is_discontinued = 1）を対象から外したか。
  • 売れるペースを見る期間（年間か、直近の数か月か）を決め、期間の境界は正しいか。
  • キャンセル・返品の注文の数量を販売数に含めていないか。
  • 在庫が 0 の商品や、最近まったく売れていない商品が、意図せず結果から落ちていないか（または意図して外したか）。
ヒント

まずは在庫数（stock）だけで考え、次に「どのくらいのペースで売れているか」と比べる方法を考えます。販売数量は有効な注文の order_items.quantity を合計します。売れていない商品も見たいなら LEFT JOIN です。

解答例を見る

解答例 1

SELECT p.id AS 商品ID,
       p.name AS 商品名,
       p.stock AS 在庫数,
       COALESCE(SUM(CASE WHEN o.status IN ('delivered', 'shipped') THEN oi.quantity END), 0) AS 年間販売数
FROM products p
LEFT JOIN order_items oi ON oi.product_id = p.id
LEFT JOIN orders o ON o.id = oi.order_id
WHERE p.is_discontinued = 0
  AND p.stock <= 10
GROUP BY p.id, p.name, p.stock
ORDER BY p.stock, p.id

解釈: 販売中（廃番でない）で、在庫が 10 個以下の商品を候補とする。判断の材料として2025年の販売数も付ける。長所: 基準が分かりやすく、すぐに出せる。在庫の少ない順に並ぶので上から確認していける。注意点: 「10 個」は仮の基準。よく売れる安い商品（ボールペンなど）は在庫が多くても足りなくなることがあり、逆にほとんど売れない高額商品が候補に入る。

解答例 2

WITH recent AS (
  SELECT oi.product_id, SUM(oi.quantity) AS qty
  FROM order_items oi
  JOIN orders o ON o.id = oi.order_id
  WHERE o.status IN ('delivered', 'shipped')
    AND o.ordered_on >= '2025-10-01' AND o.ordered_on < '2026-01-01'
  GROUP BY oi.product_id
)
SELECT p.id AS 商品ID,
       p.name AS 商品名,
       p.stock AS 在庫数,
       r.qty AS 直近3か月の販売数,
       ROUND(r.qty / 3.0, 1) AS 月平均販売数,
       ROUND(p.stock / (r.qty / 3.0), 1) AS 在庫月数,
       CAST(ceil(r.qty * 2 / 3.0) AS INTEGER) - p.stock AS 発注目安数
FROM products p
JOIN recent r ON r.product_id = p.id
WHERE p.is_discontinued = 0
  AND p.stock < r.qty * 2 / 3.0
ORDER BY 在庫月数, p.id

解釈: 直近3か月（2025-10-01〜2025-12-31）の販売ペースから「在庫が何か月分あるか」を求め、2か月分を下回る商品を候補とする。発注目安数は「2か月分にするために足りない数」。長所: 売れ行きを考えた基準なので、在庫が多くてもよく売れる商品を拾える。発注の数まで提案できる。注意点: 直近3か月に1つも売れていない商品は対象外になる。年末は需要が増える時期なので、ペースを多めに見積もっている可能性がある。「2か月分」も仮の基準で、仕入れにかかる日数を物流部に確認したい。
