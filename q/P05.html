実践 5 商品分析

商品のABC分析

（商品企画の課長より）商品数が増えてきたから、ABC分析をして、重点的に管理する商品を決めたいの。2025年のデータで、商品ごとに A・B・C のどれになるか出してもらえる？

この問題を解く（SQLを書く）

ブラウザだけで動きます。登録は不要です。

自分で確認しよう

実践問題には決まった答えがありません。結果が出たら、次の点を確かめてから、問題の画面で「完了」にしましょう。

  • 何を基準にしたか（売上金額・販売数量・粗利）を決め、その理由を説明できるか。
  • A・B・C の区切り（例: 累積 70%・90%、80%・95%）を決め、境界をまたぐ商品をどちらに入れるか決めたか。
  • キャンセル・返品の注文を売上から除いたか。
  • 一度も売れていない商品を結果に含めたか（含めるなら C）。原価が NULL の商品のように計算できないものをどう扱ったか。
  • 売上が同じ商品があるとき、累積の計算の順番が毎回同じになるか（ORDER BY に商品IDを足したか）。
  • 構成比の合計が 100% になり、商品数が元データと矛盾しないか。
ヒント

ABC分析は、商品を売上の大きい順に並べ、累積の構成比（上から足していった割合）で A・B・C に分けます。累積の合計は SUM(...) OVER (ORDER BY 売上 DESC, id) で求められます。何の大きさで並べるか（売上金額・数量・粗利）と、区切り（70%・90% など）は自分で決めます。

解答例を見る

解答例 1

WITH sales AS (
  SELECT p.id, p.name, SUM(oi.quantity * oi.unit_price) AS amount
  FROM products p
  JOIN order_items oi ON oi.product_id = p.id
  JOIN orders o ON o.id = oi.order_id
  WHERE o.status IN ('delivered', 'shipped')
  GROUP BY p.id, p.name
),
ranked AS (
  SELECT id, name, amount,
         SUM(amount) OVER (ORDER BY amount DESC, id ROWS UNBOUNDED PRECEDING) AS cum,
         SUM(amount) OVER () AS total
  FROM sales
)
SELECT id AS 商品ID,
       name AS 商品名,
       amount AS 売上金額,
       ROUND(100.0 * amount / total, 1) AS "構成比(%)",
       ROUND(100.0 * cum / total, 1) AS "累積構成比(%)",
       CASE WHEN 100.0 * (cum - amount) / total < 70 THEN 'A'
            WHEN 100.0 * (cum - amount) / total < 90 THEN 'B'
            ELSE 'C' END AS ランク
FROM ranked
ORDER BY amount DESC, id

解釈: 売上金額（delivered・shipped、送料なし）で並べ、累積 70% までを A、90% までを B、残りを C とする。「自分より上の商品までの累積（cum - amount）」が 70% 未満なら A にするので、70% をまたぐ商品は A に入る。長所: いちばん一般的なABC分析で、説明しやすい。注意点: 売れていない商品は JOIN で落ちて結果に出ない。境界の商品を A に入れるか B に入れるかで A の数が1つ変わるので、ルールを資料に書く。

解答例 2

WITH profit AS (
  SELECT p.id, p.name, p.cost,
         COALESCE(SUM(CASE WHEN o.status IN ('delivered', 'shipped')
                           THEN oi.quantity * (oi.unit_price - p.cost) END), 0) AS gross
  FROM products p
  LEFT JOIN order_items oi ON oi.product_id = p.id
  LEFT JOIN orders o ON o.id = oi.order_id
  GROUP BY p.id, p.name, p.cost
),
ranked AS (
  SELECT id, name, gross,
         SUM(gross) OVER (ORDER BY gross DESC, id ROWS UNBOUNDED PRECEDING) AS cum,
         SUM(gross) OVER () AS total
  FROM profit
  WHERE cost IS NOT NULL
)
SELECT id AS 商品ID,
       name AS 商品名,
       gross AS 粗利,
       ROUND(100.0 * cum / total, 1) AS "累積構成比(%)",
       CASE WHEN gross = 0 THEN 'C（販売なし）'
            WHEN 100.0 * (cum - gross) / total < 80 THEN 'A'
            WHEN 100.0 * (cum - gross) / total < 95 THEN 'B'
            ELSE 'C' END AS ランク
FROM ranked
UNION ALL
SELECT id, name, NULL, NULL, '要確認（原価未登録）'
FROM profit
WHERE cost IS NULL
ORDER BY 粗利 DESC NULLS LAST, 商品ID

解釈: 「もうけへの貢献」で管理したいと考え、粗利（(販売単価 - 原価) × 数量）で並べる。区切りは 80%・95%。全40商品を出し、売れていない商品は C、原価が未登録の商品は計算せず「要確認」とする。長所: 安くて大量に売れる商品より、利益を生む商品が A に来る。全商品が載るので「どの商品が抜けたか」を気にしなくてよい。注意点: 原価は現在の値で計算しているので、原価が年の途中で変わっていたら正確ではない。原価未登録の商品はランク付けできないため、商品企画に原価の登録を依頼する必要がある。
