実践 2 顧客分析

休眠顧客にクーポンを送りたい

（販促担当より）最近買ってくれていない、いわゆる休眠のお客さんに「おかえりクーポン」をメールで送りたいんです。対象者のリストを作ってもらえますか？今日は 2026-01-01 です。

この問題を解く（SQLを書く）

ブラウザだけで動きます。登録は不要です。

自分で確認しよう

実践問題には決まった答えがありません。結果が出たら、次の点を確かめてから、問題の画面で「完了」にしましょう。

  • 休眠の定義（最終購入から何日以上か）を決め、その基準日（2026-01-01）からの日数の境界が正しいか。
  • キャンセル・返品だけの注文を「購入」と数えていないか（キャンセルの注文しかない顧客がいる）。
  • 一度も購入していない会員を対象に含めるか決めたか。含めるなら、登録したばかりの人まで「休眠」にしていないか。
  • メールで送るのに、メールアドレスが NULL の顧客をどう扱ったか（除く／別に知らせる）。
  • 同じ人が二重に登録されている（佐藤 花子）ようなケースで、同じ人に2通送ったり、実は最近買っている人に送ったりしないか考えたか。
ヒント

「休眠」の定義（最後の購入から何日たったら休眠か）を自分で決め、顧客ごとの最終注文日を MAX で求めます。経過日数は julianday('2026-01-01') - julianday(最終注文日) で計算できます。一度も買っていない会員を含めるなら LEFT JOIN が必要です。

解答例を見る

解答例 1

SELECT c.id AS 顧客ID,
       c.name AS 氏名,
       c.email AS メールアドレス,
       MAX(o.ordered_on) AS 最終注文日,
       CAST(julianday('2026-01-01') - julianday(MAX(o.ordered_on)) AS INTEGER) AS 経過日数,
       COUNT(*) AS 有効注文件数
FROM customers c
JOIN orders o ON o.customer_id = c.id
WHERE o.status IN ('delivered', 'shipped')
  AND c.email IS NOT NULL
GROUP BY c.id, c.name, c.email
HAVING julianday('2026-01-01') - julianday(MAX(o.ordered_on)) >= 90
ORDER BY 最終注文日, c.id

解釈: 休眠 =「有効な注文（delivered・shipped）が過去にあり、最後の注文から 90 日以上たった顧客」。メールを送れない（email が NULL）人は除く。長所: 「以前は買ってくれていた人」に絞るので、クーポンの効果が見込みやすい。経過日数の長い順（最終注文日の古い順）に並べている。注意点: 一度も買っていない会員は INNER JOIN で落ちる。90 日という基準は仮のもので、依頼者と合意しておく。

解答例 2

WITH last_order AS (
  SELECT customer_id, MAX(ordered_on) AS last_on
  FROM orders
  WHERE status IN ('delivered', 'shipped')
  GROUP BY customer_id
)
SELECT c.id AS 顧客ID,
       c.name AS 氏名,
       COALESCE(c.email, '（メール未登録）') AS メールアドレス,
       c.registered_on AS 登録日,
       l.last_on AS 最終注文日,
       CASE WHEN l.last_on IS NULL THEN '未購入' ELSE '購入後に休眠' END AS 区分
FROM customers c
LEFT JOIN last_order l ON l.customer_id = c.id
WHERE COALESCE(l.last_on, c.registered_on) <= date('2026-01-01', '-180 days')
ORDER BY 区分, COALESCE(l.last_on, c.registered_on), c.id

解釈: 休眠 =「最後の有効な注文から 180 日以上」。一度も買っていない会員も、登録から 180 日以上たっていれば対象にし、区分の列で分ける。メール未登録の人も残して、そのことが分かるようにする。長所: 販促担当が「未購入者にも送るか」「メール以外で連絡するか」を結果を見て判断できる。注意点: キャンセルしかない顧客は「未購入」扱いになる（last_order は有効な注文だけで作っているため）。二重登録の顧客は、この SQL では別人として扱われる。名寄せ（同じ人をまとめる）が必要かは依頼者に確認する。
